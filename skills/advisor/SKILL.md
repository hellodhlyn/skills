# Advisor

Use a separate Claude Agent SDK session for independent architectural advice. The
advisor receives a short problem statement, relevant background and constraints,
and the question to answer. It receives no caller conversation history and
investigates the target repository or worktree itself.

## Workflow

1. Confirm the repository or worktree to inspect. Ask only for missing context
   needed to understand the decision; do not ask the caller to enumerate files.
   Exclude secrets and unrelated personal or customer data.
2. Read [the advice contract](references/advice-contract.md) and
   [execution and recovery](references/execution.md). Prepare only the problem,
   relevant background or constraints, and the advice sought.
3. Resolve `scripts/advisor.sh` from the installed skill root and invoke it with
   the repository path as an explicit argument. Pass the short request on stdin.
4. Preserve the complete tool result and observe a numeric terminal `exit_code`.
   If execution is still running, poll that same process. Do not launch a
   replacement while its state is unknown.
5. On success, assess the returned evidence against the repository. Keep
   unsupported or unavailable evidence explicit, and present the recommendation,
   grounds, risks, alternatives, and smallest next step in the caller's language.
   Treat the advice as evidence for the primary agent, not as approval for a
   material product, architecture, data-model, UX, or domain decision.

The runner uses the Claude Agent SDK directly with Claude Opus 5.5 at `medium`
effort, balancing complex analysis with subscription usage. It requires the
official `CLAUDE_CODE_OAUTH_TOKEN` generated by `claude setup-token`, uses a
read-only tool set and OS-enforced sandbox, and has no model, provider, or profile
selection or fallback. SDK, authentication, and sandbox errors are returned as
failures.
